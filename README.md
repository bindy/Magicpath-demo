- 工具条：底部主工具条（移动、标记、框选模式、上传文件、图片生成、视频生成、文字）、画板工具条（加文字、加图形：矩形/圆形/椭圆/箭头/直线）、右下历史缩放条（撤销、重做、25/50/100/200%/放大/缩小/显示全部元素）、顶部条（画布名双击改名、全屏、关闭）、选中图片后才出的图片节点工具条（R1 只搭条子：编辑/分图层/去背景/消除/扩图/变清晰/引用生成点后提示 R2 实现，下载只在有真实资产时可用）。

- 生成与上传说明：图片/视频生成按钮在 R1 只建 status=generating 的占位节点并明确提示未接生成服务，不假装已生成；上传是本地 blob URL，仅当前会话有效，R3 存储时按缺失资产处理。
- 右键菜单与单节点下载：复制、粘贴、剪切、删除、水平/垂直翻转、上移下移层、创建素材；粘贴新 id、位置 +40、版本重计、追溯记 copiedFrom，剪切只进一条历史；翻转只加 flipH/flipV 标志不重生图；层级只换 nodes 顺序不改长图 y 顺序。文字/简报下纯文本、图形下 SVG（`src/nodeDownload.js`），图片无真实资产时返回 null、不伪造下载。

### 分组验证结论（R1，先验证后实现，不直接假定）

结论：继续用成员列表适配层，不用 React Flow parent 节点。理由：parent 节点的位置是相对坐标（子节点位置 = 父节点绝对位置 + 相对位置），且 extent=parent 会把子节点限制在父框内、父框不会随子节点自动扩缩、拖子节点默认不带动整组、删子节点也不会自动解散父组，这些都与 M1 语义（框选成组、拖组内任意成员整组移动、删节点同步移出组、不足 2 人自动解散）冲突；用 parent 还要把 Board 的绝对世界坐标来回换算，增加适配层负担。

实现：组只存在 Board.groups 里（成员 id 列表），画布上按成员外接矩形画虚线框 overlay（按当前视口换算到屏幕坐标，不随节点重算长图顺序）；拖组内成员时按拖拽开始时的成员位置算 delta、其余成员同向移动，松手只进一条历史；删节点时同步移出组、不足 2 人自动解散。

框选验证：React Flow 的 selectionOnDrag 默认 false，且只有在 panOnDrag 不为 true 时才真正进入框选（库里 `_selectionOnDrag = selectionOnDrag && panOnDrag !== true`），所以 R1 的工具模式切换是必要的：框选模式下 panOnDrag=false、selectionOnDrag=true，移动模式下反过来；Esc 回移动模式。

## R2 已做（图片节点编辑器，板子引擎不动）

- 纯逻辑层 `src/imageEdit.js`（思路迁自 v1 `src/image-text.js`，本项目自己的代码）：图内文字层（百分比定位，改层不重生图、删层不留空、已有层不被默认层覆盖）、涂抹蒙版层（百分比矩形、笔大小 5~50% 可调、新建区域以笔大小为边长、上限 10 个、删区不留空）、改图提交（走 edit 边、新版本 +1、来源节点原样不动、非图片节点拒绝）。
- 编辑器面板（选中图片节点时）：节点设置仍只改标题/提示词；图内文字层可加/改/删（文字、字号、颜色、加粗、横纵百分比）；涂抹选区可在预览图上点选添加（以笔大小为边长）、或按“加涂抹区域”居中添加，也可直接改各区横纵宽高百分比；提交分图层/去背景/消除/扩图/变清晰/引用生成时，先把草稿落到 Board 再走 edit 边建新版本节点，整件事只进一条历史。浮动图片工具条的同名按钮也接通了同一提交（以已保存的图层/蒙版为准，未保存的先点保存）。
- 画布上的图片节点本身按百分比画出文字层和蒙版层（绝对定位 + pointer-events none，不拦截拖拽）。
- 明确未接通：改图服务、分图层的真实拆层结果、消除/扩图/变清晰的真实出图都未接通。新节点只是 status=generating 的占位（继承来源图层/蒙版作待处理输入，不是生成结果），分图层也只建一个占位节点、未拆出真实图层；消除无涂抹区时会先提示，不会静默建节点。涂抹在 R2 是面板/预览点选加区域，不是直接在画布图上拖笔刷（拖笔刷是后续改进）。

## R3 已做（存储 + Agent ops + 资产与历史导入）

- 纯逻辑层 `src/storage.js`（迁移/导出/导入/缺失检测，Node 单测可跑，不依赖 IndexedDB）：schemaVersion 只增不降（缺失或旧版升到 1、未来版本明确报错不降级）、未知字段原样保留、导出剥掉 blob URL（只留 assetId）、zip = projects.json + assets.json（元数据，不重复存 blob）、缺失资产整包拒绝、不静默丢节点。
- 纯逻辑层 `src/ops.js`：apply_ops 原子应用（任一 op 失败整批回滚、已用 clientOpId 不变）、clientOpId 去重（重放直接跳过、不重复建节点）、覆盖最小集（add/update/delete 节点、add/delete 边）与 R1 扩展（copy/paste、flip、move_layer、create_material）。
- UI 层：启动时从 IndexedDB（localforage，键 magicpath-board-v1）恢复，Board 变化后防抖 500ms 写回（写回的是剥 blob 后的板子）；“导出 zip / 导入 zip”按钮；Agent ops 面板（粘 ops JSON → 点“准备”只列待执行项 → 确认条里点“确认执行”才应用，取消则不执行）；资产与历史页签（资产 = 右键“创建素材”登记的记录，历史 = 本板 ready 节点），点“导入为新节点”按 assetId 复用、状态 ready、版本从 1 计建新节点，不覆盖原记录；图片/视频记录无 assetId 时明确报错、不建节点。
- 新增依赖：jszip（zip 导入导出）、localforage（IndexedDB）。构建会多一个 chunk 体积警告（566kB），属原型可接受范围，未做代码分割。

## 运行

```bash
cd canvas-prototype/reactflow
npm install
npm run dev     # 开发预览
npm run build   # 生产构建冒烟
npm test        # 适配层单测
```

## 冒烟标准

- `npm test` 全过（R0：缩放 clamp、Board 往返、显示全部元素大小板子、空节点；R1：节点增删改、连线校验、分组、历史、剪贴、翻转层级、创建素材、单节点下载）。
- `npm run build` 成功。
- 手动打开后（R1 清单，用户明天检查用）：
  1. 工具条：底部主工具条、画板工具条（加文字/加图形）、右下历史缩放条、顶部条（双击改名、全屏、关闭/重新打开）都可见且可点。
  2. 节点：加文字、加图形（四种形状）、图片生成占位、视频生成占位、上传文件都能建节点；点节点进右侧“节点设置”改标题/内容后保存，刷新前数据仍在板上；删节点后相关边消失。
  3. 分组：框选模式拖背景框选 ≥2 个节点后点“成组”出虚线框；拖组内任意成员，整组同向移动、松手只进一条历史（撤销一次回到拖前）；删组内节点至不足 2 人时组自动消失；点“解散分组”只解散组不删节点。
  4. 右键菜单：在节点上右键，复制后粘贴出新节点（位置偏移、版本为 1）；剪切后原节点消失且只进一条历史；图片/图形翻转只改显示方向不重生图；上移下移层只换顺序，长图段顺序（按 y）不变；创建素材后板面素材数 +1。
  5. 单节点下载：文字节点下载 txt、图形节点下载 SVG；图片占位节点点下载应提示暂无可下载资产，不应下载到假图。
  6. 不退化：拖节点、滚轮缩放、点“显示全部元素”能回到全景，缩放显示在 2%~400% 之间；移动端样式（100dvh、安全区、响应式工具条、44px 触摸目标）仍在。
  7. 未接通项应明确提示，不能假装已生成：图片/视频生成只建占位节点、标记工具只切换模式、图片工具条的编辑/分图层等点后提示 R2 实现。
- R2 追加清单：
  1. 选中图片节点：右侧出现“图内文字层”和“涂抹选区”；加文字层、改字号/颜色/加粗/横纵百分比后点保存，画布上的图应同步出现该文字（百分比位置）；删层后不留空层。
  2. 涂抹：点预览图加区域、或按“加涂抹区域”，区域数到 10 个时再加应提示“最多可添加 10 个编辑区域”且不新增；删区后计数回落；改百分比后预览与画布蒙版同步移动。
  3. 改图提交：填改图提示词、点“消除”且有涂抹区时，应在右侧新建一个版本 +1 的占位节点并连一条 edit 边，来源节点版本与图层/蒙版不变；无涂抹区点消除应只提示、不建节点；分图层只建一个占位节点，不应声称已拆出图层。
  4. 不退化：R1 清单（工具条、分组、右键菜单、单节点下载、缩放/fitView、移动端样式）仍全过。
- R3 追加清单：
  1. 持久化：改动板子后刷新页面（同一浏览器），应从本地存储恢复改动；刷新后上传的本地图片会因 blob URL 已失效而不再显示（这是设计，不是 bug：导出/存储不含 blob）。
  2. zip：点“导出 zip”得到 magicpath-board.zip，解压应有 projects.json 与 assets.json；再点“导入 zip”选它，应成功恢复；手工改一个缺资产的 zip（节点 assetId 不在 assets.json 里）导入时，应明确报缺失资产且不导入任何节点。
  3. Agent ops：点“填入示例 ops”→“准备 ops”时板子不应变化、只出确认条；点“确认执行”后多一个文字节点且图片翻转；再准备并确认同一批 ops，应全部跳过、不重复建节点；把示例里第二条改成删不存在的节点再准备确认，应整批回滚、第一条也不生效。
  4. 资产与历史：先在节点右键点“创建素材”，再在“资产”页签点“导入为新节点”，应新建 ready、版本 1 的节点；无 assetId 的图片素材导入时应明确报错、不建节点；“历史”页签选一个 ready 节点导入，同样建新节点、不改原节点。
  5. 不退化：R1、R2 清单仍全过。
